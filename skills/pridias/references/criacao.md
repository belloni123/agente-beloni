# Prioridades de criação

Escolha etapas úteis à entrega. Descubra as ferramentas disponíveis; não presuma contas, créditos ou runtimes. Preserve a governança do projeto, as referências e as escolhas explícitas do usuário.

1. Aproveite o briefing existente: objetivo, público, conteúdo, ação e referência. Para landing comercial, Copymoney conduz a copy.
2. Para estrutura nova ou mudança estrutural, prefira `draw-wireframe` com copy real, renderize e inspecione. Valide a estrutura antes do acabamento quando houver decisão pendente. Pule essa etapa para estrutura aprovada, recriação fiel, ajuste pequeno ou pedido de execução direta. `plan-screen` e `to-wireframe` permanecem alternativas quando pedidas, preservando suas políticas de invocação.
3. Para decisões de UI, UX, design system e tipografia, prefira `b16-design-intelligence`. `frontend-design` é alternativa de direção visual; `impeccable` atende refinamento ou auditoria. Não aplique três direções ao mesmo tempo. Preserve o design system existente.
4. Implemente na stack e no fluxo do projeto, usando Bell quando aplicável. Mock para HTML estático: `img2html`; `img-to-html` somente quando o processo por etapas for pedido. Não trocar React/Next por HTML estático automaticamente. Preserve os gates da skill escolhida.
5. Confira desktop/mobile, hierarquia, cortes, contraste, teclado e interações relevantes, além dos testes do projeto. Wireframe não comprova funcionalidade nem responsividade.

## Especialistas condicionais

- `b16-immersive-frontend`: motion web/3D quando a imersão apoiar o briefing. `animate`: componentes e backgrounds; `extract-ds`: extração de design system solicitada.
- `scroll-site`: experiência cinematográfica por scroll solicitada, após conferir provedor e requisitos. Geração de imagens não é obrigatória para criar uma interface comum.
- `figma:figma-design-to-code`: referência do Figma para código; `figma:figma-use` e pré-requisitos para editar no Figma.
- `stageshow`: demo ilustrada de produto; gravação do aplicativo real exige observar e capturar o aplicativo.
- `anatomy`: figura isométrica interativa; `teardown`: mecanismo 3D explorável. Não são etapas obrigatórias de sites.
- `motion-editorial`: continuidade e ritmo em vídeo; `intushub-motion`: técnica programática; `video2html`: reconstrução de UI animada a partir de vídeo.
- `to-img`, `img-to-html`, `plan-screen`, `to-wireframe`, `to-tickets` e `handoff`: preservar a política de invocação instalada.

Para `draw-wireframe`, siga seu SKILL.md e use os scripts da própria pasta. O modo bruto não precisa de API de imagem; fontes externas e runtimes dependem do ambiente. Não executar toda a coleção para uma única entrega.
